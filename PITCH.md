# TowkAI OS pitch and demo script

## One-line pitch

**TowkAI OS is a pixel-art operating system for one-person companies — one screen where a founder can see, control and approve the work of multiple AI agents across multiple projects.**

## 30-second demo script

> Solo founders already use many AI tools, but the work is scattered across chats, automations and dashboards. TowkAI OS gives them one visual control centre.
>
> On the left are my active projects and agent processes. In the middle, I can see agents moving through research, product, growth and operations. I can click any agent to inspect its task, pause it, reassign it or update its mission. When work is complete, it comes to the approval queue, where nothing ships until the founder CHOPs it.
>
> The result is one founder running a visible, controllable AI workforce from one screen.

## 60-second pitch

> TowkAI OS is a pixel-art agent IDE for one-person companies.
>
> The problem is not access to AI. The problem is agent sprawl. A solo founder may use several agents across research, product, growth and operations, but those agents live across separate chats and tools. There is no shared control plane, no clear status view and no consistent approval gate.
>
> TowkAI OS turns that invisible work into a visual operating system. Projects appear as workspaces, agents appear as running processes, and missions move through functional zones. The founder can inspect, pause, stop, reassign and re-task agents, then approve or send back outputs before they ship.
>
> This MVP uses workflows inspired by products I already operate — Flywheel, Dealmaiker, Rocketo and IgnAIte — and points toward a future marketplace of installable agent modules.

## Exact live demo flow

### 1. Establish the problem — 5 seconds
Say:

> “A solo founder may be running many AI agents, but today they are scattered across chats and tools.”

Point to the left project and agent lists.

### 2. Explain the product — 5 seconds
Say:

> “TowkAI OS puts all projects, agents, tasks and approvals into one visual control centre.”

Point to the centre map, right inspector and bottom approval queue.

### 3. Run the mission — 8 seconds
Click **RUN DEMO**.

Say:

> “Each pixel worker is an agent. You can immediately see which function it is working on and where work is moving.”

### 4. Show founder control — 7 seconds
Click an agent, then point to the inspector.

Say:

> “The founder can inspect the current task, update it, pause the agent or reassign it.”

### 5. Show human approval — 5 seconds
Click **CHOP** on an approval card.

Say:

> “Nothing ships automatically. The founder remains the final decision-maker.”

## Strong closing line

> **TowkAI OS turns one founder plus many agents from a messy collection of tools into an actual operating company.**

## Likely judge questions

### Is this connected to real agents?

> The hackathon MVP uses a deterministic simulation so the demo is reliable and requires no API key. The production architecture connects each process to real agent runtimes and workflows. The project examples already map to real workflows I have built across market research, GTM, BD automation and growth.

### Why pixel art instead of a conventional dashboard?

> Agent work is invisible and hard to understand. Spatial visualisation makes parallel work legible immediately. Pixel art also keeps the interface lightweight, distinctive and approachable without hiding the underlying controls.

### Who pays for this?

> Solo founders, micro-teams, agencies and venture studios operating multiple AI workflows. Pricing can combine project and agent subscriptions with usage-based execution fees.

### What is the moat?

> The moat is not the visual skin alone. It is the unified orchestration, project memory, human approval layer, observability and future marketplace of installable agent workflows.

### Why the Singapore backgrounds?

> They provide memorable local identity and show that the same operating system can support different work environments and user preferences without changing the underlying agent model.
